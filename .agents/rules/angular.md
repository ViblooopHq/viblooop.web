# Angular Rule

- Follow the repository's actual Angular version and established patterns.
- Inspect existing components/services/state before introducing new abstractions.
- Keep changes focused; reuse shared UI and API utilities.
- Use strict types and avoid unnecessary `any`.
- Handle async lifecycle, subscriptions, loading/error/empty states.
- Preserve accessibility, responsive layout, and existing behavior.
- Verify with applicable lint, tests, build, and browser checks.
